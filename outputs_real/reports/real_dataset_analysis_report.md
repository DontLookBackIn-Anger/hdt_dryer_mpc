## 一、数据集的工艺背景、作用与研究意义

### 1. 这批数据到底是什么工艺？
这 4 类数据均来自**烟草制丝线「加料回潮工序（增温增湿滚筒）」的 1 Hz 实时 PLC/传感器采集数据**：
- **物料变化**：入口含水率约 `16.1% ~ 17.9%` → 出口含水率约 `20.7% ~ 21.3%`（**增湿**），烟叶出口温度稳定在 `48.8℃ ~ 50.7℃`（**增温**）。
- **与你之前仿真线（HDT 气流烘丝机）的异同**：
  - **工艺方向相反**：仿真线是「脱水干燥」（20% → 12.5%，温度 ~65℃）；真实数据线是「增湿回潮」（16.5% → 20.8%，温度 ~50℃）。
  - **控制与建模范式完全相通**：二者都是典型的 **1 Hz 采样、大纯滞后（30~60s）、强一阶惯性、多变量强耦合、闭环 PID 运行的批次生产过程**。你之前在仿真线学到的「时滞辨识 → 多步滑窗预测 → 物理一致性校验 → MPC 闭环优化」全套方法论可以无缝迁移。

### 2. 四个数据集各自的作用与定位

### 3. 这批数据对你的研究意义
1. **打破“仿真完美假设”**：仿真数据没有时间断层、没有传感器量化台阶、没有极值毛刺、没有未测扰动和闭环反馈混叠；真实数据把工业现场的所有难点一次性暴露出来，你的工作如果能妥善解决这些问题，工程与论文含金量会大幅提升。
2. **验证“预测服务于控制（MPC）”**：原资料附带的在线脚本 `predict.py` 明确给出了现场 DMC（动态矩阵控制）的真实需求——**用过去 60 秒预测未来 60 秒的出口含水率与出口温度**，直接为你定义了真实的建模任务指标。

## 二、数据集质量全面体检：发现的 9 大问题与解决办法

下面按**严重程度**逐一列出通过脚本诊断出的真实问题、具体数据证据以及可落地的工程解决办法。

---

### 【严重级】直接导致模型训练失效或结果作废的问题

#### 问题 1：`1A.csv` 稳态段内部存在 204 秒时间断层
- **证据**：`1A.csv` 共 5,231 行，时间跨度却为 5,433 秒；在第 **1470 行**（`2025-01-26 08:40:37 → 08:44:01`）出现单步跳变 **204 秒（3.4 分钟）**，且恰好落在稳态生产阶段内。
- **危害**：若直接按行号做 60s 滑窗或算互相关/滞后，会在断层处拼接出“时间跨越 3.4 分钟的假样本”，污染滞后辨识与序列模型梯度。
- **解决办法**：
  - 在清洗阶段强制计算 `dt = timestamp.diff()`，凡 `dt > 1.5s` 即切分 `time_seg_id`。
  - 时滞辨识与滑窗构造**严格在连续 `time_seg_id` 内部独立执行**，绝不跨断层拼接（已在 [r1_clean_and_explore.py](file:///home/atlsa/hdt_dryer_mpc/src_real/r1_clean_and_explore.py) 中实现，提取出 `1A` 最长连续 1 Hz 稳态段 3,280s）。

#### 问题 2：`batches/*.txt` 存在极端传感器毛刺（`col13` 飙升至 `9966.13`）
- **证据**：在 18 个批次的稳态段中：
  - `col 13` 正常范围 `p01=0.00 ~ p99=19.57`（中位数 `6.89`），但在 `20250318T135227.txt` 中飙升至 **`9966.133`**（高出正常值 500 倍！）。
  - `col 12` 正常 `p99=58.64`，极值达 **`724.20`**；`col 11` 正常 `p99=29.00`，极值达 **`81.82`**。
- **危害**：如果直接套用原代码里的 `MinMaxScaler`，一个 `9966` 极值会把 99.9% 的正常数据压缩进 `[0, 0.002]` 的狭小区间，导致神经网络梯度消失或特征完全失效。
- **解决办法**：
  1. 在特征缩放前，按**物理上下限 + 分位数截断（如训练集 `[p0.1, p99.9]` 或 Hampel 滑动中值滤波）**清除单点毛刺；
  2. 优先使用 **`RobustScaler`（基于中位数与 IQR）** 或 **截断后的 `StandardScaler`** 替代原始 `MinMaxScaler`，且**只在训练集上 `fit`**，严禁在切分测试集前全量 `fit`。

#### 问题 3：`transformer_data.csv` 并非纯稳态，末尾混入 156 秒停机降温段与剧烈阶跃
- **证据**：
  - 索引 `4116 ~ 4271`（最后 156 行）：`outlet_temp` 从 `50.4℃` 骤降至 **`36.70℃`**，`steam_flow` 有 180 行跌至 `< 1`（停汽）；
  - 全程中 `steam_flow` 出现单秒跳变 `90.87`（峰值 `217.94`），`water_flow` 出现单秒跳变 `34.85`（在 ~35 与 ~7.8/0 之间切换）。
- **危害**：
  - 这直接导致我们在 `r2` 中用线性 FOPDT 拟合 `transformer_data.csv` 的出口温度时 $R^2$ 骤降至 `0.049`；
  - 更隐蔽的是：原代码 `train.py` 按 `test_size=0.07, shuffle=False` 切分，测试集正好落在最后 299 行，**把停机降温段当成了正常稳态测试集**！
- **解决办法**：
  - 对 `transformer_data.csv` 同样施加稳态过滤（例如剔除末尾 `outlet_temp < 45℃` 或 `steam_flow < 1` 的停机段，仅保留前 ~4,080 行稳定生产段）；
  - 对 `water_flow` 的大工况切换，在分析时标注为**工况切换事件（Regime Shift）**，测试模型对阶跃工况的适应能力。

#### 问题 4：`batches/*.txt` 缺少表头与时间戳（16 列语义未完全锁定）
- **证据**：18 个 `.txt` 文件均为纯逗号分隔数字，无列名、无时间戳。目前通过与 `1A.csv` 比对已高置信度锁定 8 个核心列（`col0` 流量、`col1` 入口水分、`col3` 蒸汽流量、`col4` 蒸汽阀位、`col5` 出口温度、`col6` 加水流量=0、`col8` 出口水分、`col10` 回风温度），但 `col2 / col7 / col9 / col11~15` 尚未有官方点表确认。
- **危害**：盲目把未知列喂进模型，可能引入**目标泄露列**（例如某个衍生列是未来值或控制器内部误差）或无意义噪声，也无法在论文中解释物理含义。
- **解决办法**：
  - **最佳做法**：向数据提供者索要一份 16 列 PLC 点表；
  - **过渡做法（立即可行）**：先仅使用已 100% 确认物理意义的 **7 个核心动态列**（`col0, 1, 3, 4, 5, 8, 10`）构建跨 18 批次的标准训练集，与 `1A.csv` / `1B.csv` 保持完全一致的特征空间，确保零泄露、强可解释。

### 【中等级】影响建模精度、泛化性与物理可解释性的问题

#### 问题 5：强闭环 PID 反馈混叠（原始互相关失真）
- **证据**：在 [r2_delay_identification.txt](file:///home/atlsa/hdt_dryer_mpc/outputs_real/reports/r2_delay_identification.txt) 中，`1B` 的 `steam_flow → outlet_moisture` 原始互相关在 **0 秒**出现 $r = -0.790$（强负相关），而实际物理上加蒸汽应使含水率升高且有几十秒滞后。原因是现场 PID 控制器在水分偏低时立刻开大蒸汽，造成了“输出反过来驱动输入”的闭环伪相关。
- **解决办法**：
  - 做滞后辨识时必须结合**一阶差分预白化互相关 + ARX 滞后扫描 + MIMO 联合辨识**（已在 `r2` 中验证：蒸汽通道真实滞后集中在 **32~53 秒**）；
  - 构建预测模型时，输入窗口必须覆盖完整滞后（`input_size ≥ 60~90s`），并在后续 `s4` 风格的评估中加入**物理方向一致性检验**（验证 $\partial \hat{y}_{\text{moist}} / \partial u_{\text{steam}} > 0$，防止黑箱模型学反因果关系！）。

#### 问题 6：强一阶惯性 + 传感器量化台阶，极易产生“单步预测虚高陷阱”
- **证据**：
  - `1A`/`1B` 出口含水率传感器分辨率仅 `0.01%`，稳态段最长连续数值不变（冻结）达 **35~41 秒**，单秒最大变化仅 `0.01%`；
  - 三个数据集稳态段出口含水率的 $\text{ACF}(1\text{s}) > 0.99$（衰减到 0.5 需 **42~74 秒**）。
- **危害**：如果像原 `train.py` 那样用包含历史 `y` 的特征只预测下一秒（`target_time_step=1`），哪怕直接输出 `y(t+1) = y(t)`（Naive 基线）都能轻松拿到 $R^2 > 0.98$，但对 30~60 秒后的 MPC 控制毫无价值。
- **解决办法**：
  - 严格锁定**多步预测任务**（如 `horizon = 30s, 60s` 或同时输出未来 `1..60s` 轨迹）；
  - 任何模型必须以 **Naive（保持当前值）** 和 **线性 ARX/Ridge** 为基线，只有显著战胜基线（尤其是 30s/60s 处）才算有效。

#### 问题 7：工况与执行器差异（`water_flow` 全零 & 跨批次分布漂移）
- **证据**：
  - `1A.csv`、`1B.csv` 以及全部 18 个 `batches/*.txt` 中，`water_flow`（加水流量）**100% 为 0**，而 `transformer_data.csv` 中 `water_flow` 在 `0 ~ 35.5` 剧烈变化；
  - 18 个批次之间存在明显均值漂移：出口温度均值在 `48.76℃ ~ 50.65℃` 之间移动，入口含水率在 `16.06% ~ 16.63%` 之间移动，`col2` 呈现 `~201.6` 和 `~230.2` 两个明显档位（疑似不同牌号/配方设定）。
- **解决办法**：
  - 建模前自动剔除零方差常量列（避免归一化除零或引入无效权重）；
  - **绝对不能把 `batches/*.txt` 拼成一张大表后随机打乱划分训练/测试集**——必须**按完整批次划分**（例如 14 个批次训练 + 2 个批次验证 + 2 个批次测试），并采用**窗口内相对变化量（Δ特征 / 实例归一化 RevIN）**来抵抗跨批次基准漂移。

### 【轻微级】格式细节与低信息量特征问题

#### 问题 8：文件编码与脏列格式不统一
- **证据**：`1B.csv` 行尾多逗号产生全 `NaN` 列 `Unnamed: 12`；`transformer_data.csv` 首列含 UTF-8 BOM（`\ufeff`）；`1A`/`1B` 为中文表头，`transformer_data` 为英文点名，`batches` 无表头。
- **解决办法**：通过统一的读取适配层（已在 [real_common.py](file:///home/atlsa/hdt_dryer_mpc/src_real/real_common.py) 建立 `utf-8-sig` 读取 + 自动剔除 `Unnamed`/全空列 + 统一英文 Schema）一次性解决。

#### 问题 9：部分辅助变量量化过粗、稳态几乎不变
- **证据**：`1A` 中 `steam_pressure` 稳态分辨率仅 `0.01 MPa`，最长连续不变达 **517 秒**（标准差仅 `0.0042`）；`feed_rate` 在稳态下由电子皮带秤紧闭环控制，标准差仅 `1.59 kg/h`（相对波动 `< 0.04%`）。
- **解决办法**：稳态建模中此类近常量特征贡献极小，可通过特征重要性 / 相关性筛选精简输入维度，把模型容量集中在高信息量变量（`steam_flow`、`steam_valve`、`inlet_moisture`、`return_air_temp`、`exhaust_air_flow`）上。
